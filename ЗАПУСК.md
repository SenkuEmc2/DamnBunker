# Запуск Discord-бота

Проект находится в `D:\Codex\Бункер`. Python-окружение и зависимости на этом компьютере уже подготовлены. Для первой настоящей партии осталось подключить собственное приложение Discord.

## 1. Создать приложение Discord

1. Открой [Discord Developer Portal](https://discord.com/developers/applications) и создай приложение через **New Application**.
2. В разделе **Bot** получи токен бота. Вставь его только в локальный файл `.env`, в строку `DISCORD_TOKEN=`. Токен не нужно отправлять в чат.
3. В разделе **Installation** включи **Guild Install**, выбери области доступа `bot` и `applications.commands`.
4. Дай боту права **View Channels**, **Send Messages**, **Embed Links**, **Read Message History**. Для игры в ветках также нужно **Send Messages in Threads**. Права администратора и доступ к содержимому сообщений не нужны.
5. Открой ссылку установки приложения и добавь его на свой сервер.
6. В Discord включи режим разработчика: **Настройки пользователя → Расширенные → Режим разработчика**. Скопируй ID сервера через его контекстное меню и впиши в `DISCORD_GUILD_ID=` в `.env`.

Файл `.env` выглядит так:

```dotenv
DISCORD_TOKEN=токен_вашего_бота
DISCORD_GUILD_ID=числовой_id_сервера
```

`DISCORD_GUILD_ID` направляет команды на выбранный тестовый сервер. Без него бот регистрирует глобальные команды. Не публикуй `.env` вместе с проектом; он уже добавлен в `.gitignore`.

Путь настройки основан на [официальной инструкции Discord](https://docs.discord.com/developers/quick-start/getting-started). Названия некоторых разделов могут отличаться по языку интерфейса.

## 2. Запустить

Дважды нажми `start.cmd`. Держи окно открытым во время игры. После подключения в нём появится строка `Discord connected as ...`. Бот работает, пока запущен компьютер и есть интернет.

Если переносишь проект на другой компьютер: установи Python 3.11 или новее с pip и сначала запусти `setup.cmd`. Он установит зависимости и создаст пустой `.env`, если такого файла ещё нет. Проверенная здесь версия Python — 3.13.

Запуск из PowerShell:

```powershell
Set-Location 'D:\Codex\Бункер'
.\.venv\Scripts\python.exe -B -m bunker.bot
```

## 3. Первая партия

Соберитесь в голосовом канале. В текстовом канале введи:

```text
/bunker players:6 public:True decision:True events:False automatic:False
```

Discord покажет эти параметры как поля команды:

| Параметр | Значение |
|---|---|
| `players` | От 4 до 12 участников; столько человек должно войти до старта |
| `public` | Открытые голоса. `False` включает тайные |
| `decision` | Одно общее решение в финале. `False` — автоматический финал |
| `events` | Одно случайное событие во втором круге |
| `automatic` | Автоматические переходы после таймера. По умолчанию этапы переключает ведущий |

Создатель входит автоматически и становится ведущим. Остальные нажимают **Войти**. Ведущий может настроить **Таймеры** и передать свою роль другому участнику до старта. Затем нажимает **Следующий этап**.

- **Мои карты** — личная рука, спецкарта и свой текущий голос. Ответ видит только нажавший игрок.
- **Карты игроков** — полный список уже открытых характеристик. Панель в канале показывает сокращённый список.
- **Раскрыть карту** — выбор характеристики в личном меню.
- **Голосовать** — выбор кандидата, участника события или финального решения.
- **Особые условия** — описание своей спецкарты, выбор цели и применение.
- **Следующий этап** — ведущий закрывает текущий этап. На раскрытии бот случайно выбирает пропущенные карты; пропущенные голоса считаются воздержанием.
- **Пауза / продолжить** — сохраняет остаток таймера и приостанавливает игровые действия.
- **Остановить партию** — отдельное подтверждение ведущего; запись игры сохраняется.

Когда проголосовали все, начинается отдельное окно смены голоса. Каждый может изменить выбор один раз. В ручном режиме ведущий закрывает это окно кнопкой **Следующий этап**. При ничьей идут защита и повторное голосование; при повторной ничьей — жребий среди лидеров.

Тайное голосование скрывает выбор остальных до подсчёта. Итог показывает количество голосов по кандидатам. Финальное решение всегда тайное; побеждает большинство, при равенстве выбирается отопление.

## Таймеры

Настраиваются в лобби, каждый от 0 до 3600 секунд. Ноль выключает таймер, и переход делает ведущий. Время раскрытия задаётся на весь круг, обсуждение используется также для защиты, время финала — также для выбора участника события.

| Игроков | Раскрытие всего круга | Обсуждение | Голосование | Смена голоса | Событие / финал |
|---|---:|---:|---:|---:|---:|
| 4–6 | 45 секунд × число игроков | 120 | 45 | 30 | 90 |
| 7–9 | 45 секунд × число игроков | 180 | 60 | 30 | 90 |
| 10–12 | 45 секунд × число игроков | 240 | 75 | 45 | 90 |

В ручном режиме истечение времени отмечается на панели, а этап завершает ведущий. В автоматическом бот завершает его сам. Ведущий может переключить этап раньше. После всех раскрытий обсуждение начинается сразу, после всех первых голосов сразу начинается окно смены.

## Сохранение и восстановление

Партии сохраняются в `data/games.sqlite3` после каждого действия. После перезапуска бот восстанавливает активные партии, кнопки и сроки таймеров. Просроченный автоматический этап завершается один раз; новый этап получает полный новый таймер.

`/bunker_resume` обновляет панель текущей партии в этом канале, а при её отсутствии создаёт заново. `/bunker_help` показывает краткие правила. В одном канале может быть одна активная партия; в разных каналах партии независимы.

Закрытие окна программы останавливает бота; для короткого перерыва сначала поставь партию на паузу. Не запускай два экземпляра бота одновременно с одной базой.

## Что входит в первую сборку

- 4–12 игроков, 6 / 7 / 8 характеристик на человека и дополнительная спецкарта. Вместимость — половина начального лобби с округлением вниз.
- 378 вариантов обычных карт и 18 спецкарт. Биология создаётся при раздаче. Это авторские карты проекта, не полная копия официальной колоды.
- Случайный совместимый бункер, запасы, системы и две разные детали: первая открыта сразу, вторая — до раскрытий второго круга.
- Рейд и незнакомец: включаются общей настройкой. Рейд доступен от 8 игроков; участник отсутствует одно голосование, затем возвращается с едой или погибает. Места в бункере не меняются.
- До закрытия бункера остаётся минимум одна скрытая характеристика. Спецкарта в этот минимум не входит. В финале история называет только карты, использованные при расчёте.

**Для первого теста подключён финал «Сильный мороз».** Другие 11 катастроф сохранены в JSON как заготовки, но пока не выбираются Discord-ботом. Итог представляет собой историю по правилам и шаблонам; внешняя нейросеть и платный API не нужны.

Порог рейда, таймеры, вместимость и числа карт — стартовые значения для тестирования с друзьями. Их можно пересмотреть после первой партии.

## Как считается мороз

Сочетания берутся из `cards/catastrophes.json`, включая закрытые карты финалистов и открытые детали бункера:

- Тепло без электричества: зимний опыт + тёплое снаряжение либо умение утеплять + тёплое снаряжение.
- Ремонт отопления: электрика/ремонт + мастерская либо инженерия + ремонт. При резервном питании нужен выбор «отопление»; штатное питание позволяет сохранить тепло и при выборе радио.
- Ранняя эвакуация: выбор «радио» и радиоустройство/радиорубка + радист либо источник питания/сигнала. Ожидание — одни сутки.
- Без ранней эвакуации нужно переждать весь срок бункера. На каждый день нужен запас по одной порции еды и воды на человека.
- Если общую систему обогрева наладить не удалось, ранней эвакуации доживают персонажи с личной защитой от холода. В противном случае они погибают.
- Пробное строгое правило дефицита: если запасов не хватает на всю группу до выбранного срока, выживших нет. Индивидуальное деление последних порций пока не моделируется.

Это игровой алгоритм, который предстоит сбалансировать. Здоровье, фобии, возраст, стаж, площадь, количество коек и текст состояния отопления пока служат аргументами при обсуждении и не дают самостоятельных штрафов или бонусов в расчёте мороза. Электропитание, срок, еда, вода, метки полезных карт и оснащение уже влияют на исход. Сюжета с убийством всех скрытым маньяком в этой сборке нет.

## Проверка без Discord

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -B -m tools.simulate
```

Первая команда проверяет правила, меню и сохранения без подключения к Discord. Вторая создаёт `Пример партии.md`. Тестовые базы остаются в `data/test-runs`, рабочую базу они не меняют.

Живое подключение и нажатия реальных игроков нужно проверить после настройки токена на тестовом сервере.
